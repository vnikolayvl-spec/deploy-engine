# SYSTEM SPECIFICATION FOR LLM: Generating `category.json` and Category Hierarchy for Deploy Engine

Этот документ содержит строгую техническую спецификацию для языковых моделей (LLM / AI-агентов) по проектированию иерархии папок категорий и генерации файлов **`category.json`** в **Deploy Engine**.

---

## 1. Архитектурные инварианты (CRITICAL RULES)

1. **Строгое разделение ответственности:**
   - **`category.json`** используется **ТОЛЬКО** для описания папок категорий и подкатегорий.
   - **`manifest.json`** используется **ТОЛЬКО** для описания устанавливаемых пакетов (см. `LLM.manifest.md`).
   - **ЗАПРЕЩЕНО** использовать `manifest.json` для описания категории.
   - **ЗАПРЕЩЕНО** класть `category.json` и `manifest.json` в одну и ту же конечную директорию пакета.
2. **Необязательность `category.json`:**
   - Категория определяется самим фактом существования папки, внутри которой (напрямую или во вложенных подпапках) находятся пакеты с `manifest.json`.
   - Если для категории достаточно отображать имя самой папки на диске, имеет дефолтную сортировку (`order: 100`), активна (`active: true`) и доступна на всех ОС (`platforms: []`), файл `category.json` **создавать не требуется**.
   - Создавайте `category.json` тогда, когда нужно задать человекочитаемый заголовок (`title`), описание (`desc`), порядок сортировки (`order`), ограничение по ОС (`platforms`) или отключить ветку (`"active": false`).
3. **Произвольная глубина вложенности:**
   - Дерево категорий поддерживает любую глубину вложенности (`cat1/cat2/cat3/<pkg_dir>/manifest.json`).
   - В TUI и в реестре путь категории в точности повторяет относительный путь папок от корня репозитория пакетов.

---

## 2. Формальная JSON-схема `category.json`

Все поля в `category.json` являются необязательными (`optional`):

```json
{
  "name": "string (optional, default: имя текущей директории на диске)",
  "title": "string (optional — отображаемый заголовок категории в TUI на русском языке)",
  "desc": "string (optional, alias: \"description\" — краткое описание категории в TUI)",
  "active": true,
  "order": 100,
  "platforms": ["linux", "macos"],
  "meta": {
    "key": "any custom metadata"
  }
}
```

## 3. Семантика каждого ключа и поведение парсера (`CategoryManifestParser`)

### 3.1. `title` и `name` (Правило отображения пути в TUI)
- Если в `category.json` задан `title` (или `name`, отличающийся от физического имени папки), TUI выводит человекочитаемый заголовок **вместе с относительным путем папки в квадратных скобках**:
  `📁 <title> [<относительный_путь>/] (<desc>)`
  Например, для `network/vpn/category.json` с `"title": "VPN и туннели"`:
  `[ ] 📁 VPN и туннели [network/vpn/] (Защищенные каналы связи)`
- Если ни `title`, ни кастомный `name` не заданы (или `category.json` отсутствует), TUI выводит относительный путь папки без дублирования скобок:
  `[ ] 📁 network/vpn`

### 3.2. `desc` (синоним `description`)
- Строка с кратким пояснением содержимого категории (рекомендуется 3–8 слов без точки в конце).
- Отображается в дереве TUI в круглых скобках после названия категории.

### 3.3. `active` (синоним `enabled`)
- Булево значение (`true` / `false`, по умолчанию `true`).
- **Каскадный эффект:** если в папке категории указано `"active": false`, то эта категория, **все вложенные в нее подкатегории** и **все находящиеся внутри пакеты** автоматически получают `active: false` и полностью скрываются из дерева TUI.

### 3.4. `order`
- Целое число (`integer`, по умолчанию `100`).
- Управляет вертикальным порядком категорий одного уровня в дереве TUI.
- Категории сортируются по ключу `(order, path_name.lower())`.
- Рекомендуемая шкала значений `order`:
  - `10–30`: Базовые системные и ядерные компоненты (`core`, `system`, `security`)
  - `40–60`: Сетевая инфраструктура и сервисы (`network`, `vpn`, `proxy`)
  - `70–90`: Прикладные сервисы, бэкапы, мониторинг (`backup`, `monitoring`, `media`)
  - `100`: Значение по умолчанию
  - `900+`: Вспомогательные, экспериментальные или архивные разделы

### 3.5. `platforms` (синоним `os`)
- Массив строк в нижнем регистре (или строка через запятую). По умолчанию `[]` (поддерживаются все ОС).
- Допустимые значения: `"linux"`, `"macos"`, `"darwin"`, `"debian"`, `"ubuntu"`, `"alpine"`, `"arch"`, `"fedora"`, `"rhel"`, `"centos"`.
- **Каскадное пересечение (`_merge_platforms`):**
  - Если родительская категория задает `"platforms": ["linux"]`, то все вложенные подкатегории и пакеты внутри неё наследуют ограничение `["linux"]`.
  - Если родительская категория задает `["linux", "debian", "ubuntu"]`, а дочерняя подкатегория или пакет задает `["ubuntu"]`, результирующим множеством будет их пересечение `["ubuntu"]`.

### 3.6. `meta`
- Произвольный JSON-словарь (`dict`) для хранения дополнительных пользовательских атрибутов (теги, ответственная команда, ссылки на документацию). Не влияет на UI напрямую, но сохраняется в скомпилированном `packages.json`.

## 4. Эталонные шаблоны для генерации

### Шаблон 1: Корневая категория с высоким приоритетом
Путь: `<repo>/security/category.json`
```json
{
  "title": "Безопасность и аудит",
  "desc": "Межсетевые экраны, защита SSH и аудит системы",
  "active": true,
  "order": 20,
  "platforms": ["linux", "macos"]
}
```

### Шаблон 2: Специализированная Linux-подкатегория
Путь: `<repo>/security/firewall/category.json`
```json
{
  "title": "Сетевые экраны Linux",
  "desc": "Правила nftables, iptables и fail2ban",
  "active": true,
  "order": 10,
  "platforms": ["linux"]
}
```

## 5. Чек-лист самопроверки для LLM перед выдачей ответа

1. [ ] Находится ли `category.json` строго в папке категории, а не внутри конечной папки пакета с `manifest.json`?
2. [ ] Используются ли в `category.json` только разрешенные ключи (`name`, `title`, `desc`/`description`, `active`/`enabled`, `order`, `platforms`/`os`, `meta`)?
3. [ ] Отсутствуют ли в `category.json` пакетные ключи (`units`, `sys_packages`, `requires`, `post_install`)?
4. [ ] Является ли `order` целым числом (`int`), а `active` — булевым значением (`bool`)?
5. [ ] Не противоречит ли `platforms` дочерней категории или пакета списку `platforms` родительской категории (их пересечение не должно быть пустым, если в родительской категории список не пуст)?
