# Инструкция по созданию категорий и файла `category.json`

В **Deploy Engine** структура категорий и подкатегорий строится на основе физической иерархии папок в репозитории пакетов.
Для дополнительной настройки отображения, сортировки, фильтрации по ОС и описания папки категории используется файл **`category.json`**.

> **Главное правило разделения:**
> - **`category.json`** описывает **только директорию категории** (папку/подпапку в дереве).
> - **`manifest.json`** описывает **только устанавливаемый пакет** (см. `README.manifest.md`).

---

## 1. Необязательность `category.json` и вложенность папок

1. **Файл `category.json` является полностью необязательным.**
   Если вам достаточно, чтобы категория в дереве TUI называлась так же, как сама папка на диске (например, `network` или `network/vpn`), создавать `category.json` **не нужно** — движок автоматически обнаружит все папки, внутри которых (на любом уровне вложенности) есть пакеты с `manifest.json`.
2. **Произвольная глубина вложенности.**
   Вы можете создавать цепочки папок любой глубины:
   `network/vpn/wireguard/`, `security/audit/linux/`, `media/transcoding/`.
   При этом `category.json` можно разместить на любом из уровней (только в корневой папке, только во вложенной или в каждой из них).
3. **Отображение имени и пути в TUI.**
   - Если `category.json` отсутствует или в нем не переопределено имя, в дереве TUI отображается путь папки:
     `[ ] 📁 network/vpn`
   - Если в `category.json` задан человекочитаемый заголовок `title` (или `name`, отличающийся от имени папки на диске), в TUI отображается и заголовок, и точный относительный путь папки в квадратных скобках:
     `[ ] 📁 VPN и туннелирование [network/vpn/] (Клиенты и серверы защищенной связи)`

## 2. Все поддерживаемые ключи `category.json`

Все поля в файле `category.json` являются необязательными (`optional`). Вы можете указать только те ключи, которые хотите переопределить:

| Ключ | Синонимы | Тип | По умолчанию | Описание |
| :--- | :--- | :--- | :--- | :--- |
| **`title`** | — | `string` | `""` *(имя папки)* | Человекочитаемое название категории для отображения в дереве TUI (например, `"Сетевая инфраструктура"`). Когда задан `title`, в TUI рядом с ним в квадратных скобках также выводится путь папки `[network/]`. |
| **`name`** | — | `string` | Имя папки на диске | Системное или альтернативное название категории. Если `title` не указан, а `name` отличается от имени папки на диске, `name` используется как отображаемый заголовок категории. |
| **`desc`** | **`description`** | `string` | `""` | Краткое описание категории. В дереве TUI выводится в круглых скобках после названия и пути папки: `(Инструменты мониторинга и логирования)`. |
| **`active`** | **`enabled`** | `boolean` | `true` | Флаг активности категории. Если установлено `false`, эта категория, **все вложенные в нее подкатегории и все находящиеся внутри пакеты** деактивируются и скрываются из дерева TUI. |
| **`order`** | — | `integer` | `100` | Числовой приоритет сортировки папки среди соседних категорий того же уровня. Чем **меньше** число, тем **выше** папка располагается в дереве TUI (например, `10` будет выше `50` и `100`). При одинаковом `order` папки сортируются по алфавиту. |
| **`platforms`** | **`os`** | `list[str]` или `str` | `[]` *(все ОС)* | Фильтр поддерживаемых операционных систем для всей категории (например, `["linux"]` или `["macos"]`). Наследуется всеми вложенными подкатегориями и пакетами внутри этой директории. |
| **`meta`** | — | `dict` | `{}` | Произвольный JSON-объект с пользовательскими метаданными (например, `{"owner": "infra-team", "tags": ["core", "tier-1"]}`). Сохраняется в реестре `packages.json`. |

## 3. Правила иерархического наследования (Родитель -> Подкатегория -> Пакет)

Когда категории вложены друг в друга (например, `system/` -> `system/linux-kernel/` -> пакет `sysctl-tuning`), Deploy Engine применяет строгие правила каскадного наследования:

1. **Наследование активности (`active` / `enabled`):**
   - Категория или пакет активны **только если** активны все их родительские папки.
   - Достаточно поставить `"active": false` в корневом `system/category.json`, чтобы временно отключить всю ветку `system/*` вместе со всеми подкатегориями и пакетами.
2. **Наследование и пересечение платформ (`platforms` / `os`):**
   - Если у родительской категории `platforms` не задан (`[]` — все ОС), дочерняя подкатегория или пакет используют собственный список `platforms`.
   - Если у родительской категории задан `platforms` (например, `["linux", "debian", "ubuntu"]`), а у вложенной подкатегории или пакета — `["debian"]`, итоговым списком поддерживаемых платформ становится **пересечение** множеств (`["debian"]`).
   - Если в родительской категории указано `"platforms": ["linux"]`, ни один пакет внутри неё не будет показан при выборе целевой ОС `macos` (даже если в самом пакете `platforms` пуст).
3. **Сортировка дерева (`order`):**
   - Сортировка по `order` выполняется независимо на каждом уровне иерархии папок (сначала сортируются корневые категории по их `order`, а внутри каждой корневой категории — её прямые подкатегории по их собственному `order`).

## 4. Примеры использования `category.json`

### Пример 1. Минимальный `category.json` (только заголовок и описание)
Файл `network/category.json`:
```json
{
  "title": "Сеть и маршрутизация",
  "desc": "Сетевые утилиты, фаерволы и VPN-туннели"
}
```
Отображение в TUI:
`[ ] 📁 Сеть и маршрутизация [network/] (Сетевые утилиты, фаерволы и VPN-туннели)`

### Пример 2. Полный `category.json` с сортировкой, фильтром ОС и метаданными
Файл `network/vpn/category.json`:
```json
{
  "name": "vpn",
  "title": "VPN и криптотуннели",
  "desc": "Клиенты и серверы WireGuard, Xray и OpenVPN",
  "active": true,
  "order": 10,
  "platforms": ["linux", "macos"],
  "meta": {
    "maintainer": "netops",
    "security_tier": "critical"
  }
}
```
Отображение в TUI (внутри `network/`):
`[ ] 📁 VPN и криптотуннели [network/vpn/] (Клиенты и серверы WireGuard, Xray и OpenVPN)`

### Пример 3. Отключение устаревшей ветки пакетов
Файл `legacy/category.json`:
```json
{
  "title": "Архивные пакеты",
  "desc": "Устаревшие сервисы (отключены в TUI)",
  "active": false,
  "order": 999
}
```

## 5. Пример комбинированного дерева репозитория

Ниже показано, как папки с `category.json`, папки без `category.json` и папки пакетов с `manifest.json` работают вместе:

```text
my-packages-repo/
├── core/                           # Категория 1-го уровня (с category.json, order: 10)
│   ├── category.json               # {"title": "Базовая система", "order": 10}
│   └── logging/                    # Пакет (содержит manifest.json)
│       ├── manifest.json
│       └── scripts/
├── network/                        # Категория 1-го уровня (БЕЗ category.json — используется имя "network")
│   └── vpn/                        # Подкатегория 2-го уровня (с category.json)
│       ├── category.json           # {"title": "VPN клиенты", "desc": "Защищенные туннели"}
│       ├── wireguard/              # Пакет 1 в категории network/vpn
│       │   └── manifest.json
│       └── xray/                   # Пакет 2 в категории network/vpn
│           └── manifest.json
└── macos-tools/                    # Категория только для macOS
    ├── category.json               # {"title": "Утилиты macOS", "platforms": ["macos"], "order": 50}
    └──menubar-monitor/             # Пакет (унаследует platforms: ["macos"])
        └── manifest.json
```

> **Важно:** Не кладите `category.json` и `manifest.json` в одну и ту же конечную папку пакета. Папка либо является категорией (контейнером для подпапок и пакетов и может содержать `category.json`), либо является конечным пакетом (содержит `manifest.json` и его ресурсы).
