# 🔧 Deploy Engine (версия 3.1.0)

**Deploy Engine** — модульный, кроссплатформенный и автономный оркестратор развертывания инфраструктуры в концепции **Infrastructure-as-Code (IaC)** на Python.

Движок позволяет декларативно управлять системными службами (`systemd` в Linux и `launchd` `.plist` в macOS), веб-модулями (`type: "web"`), исполняемыми скриптами, конфигурационными файлами, директориями, правами доступа, постоянными динамическими данными (базами данных), резервными копиями и защищенными переменными окружения с помощью JSON-манифестов (`manifest.json` и `category.json`).

---

## ✨ Ключевые возможности

- **Единая точка входа (`files/main.py`)**:
  - Запуск без CLI-команды (или с флагом `--tui` / `-u`) открывает интерактивный графический TUI-интерфейс (с отображением версии в заголовке и сохранением раскрытых веток дерева при пересборке).
  - Запуск с командой (`install`, `uninstall`, `reinstall`, `upgrade`, `config`, `backup`, `restore`, `list`, `info`, `completion`, `scan`, `version`, `help`) или флагами `--version` (`-V`), `--info` (`-i`) работает в CLI-режиме.
  - Детерминированный порядок установки: жесткие `requires` (с валидацией SemVer-ограничений `>=`, `<=`, `~=`, `==`, `!=`), затем мягкие `"after"` среди пакетов плана, затем исходный порядок аргументов CLI.
  - Поддержка версионирования SemVer для пакетов и движка (`min_engine_version`, `version_history` в `state.json`, команда `upgrade [pkg|all]` с автобэкапом).
  - Точечное обновление отдельных юнитов (`deploy-engine reinstall <pkg>:<unit>`, `--only`, `--unit-type`, пропуск `post_install` по умолчанию до передачи `--with-hooks`) и нативный тип юнита `"type": "web"` (`{{OPT_DIR}}/de_<pkg>/web`).
  - Развернутые маркеры `.env`: `#AUTO#`, параметризованная генерация `#GEN#` / `#GEN:token:N#` / `#GEN:hex:N#` / `#GEN:pass:N#` / `#GEN:pass_strong:N#` / `#GEN:uuid#` / `#GEN:b64:N#` / `#GEN:port:MIN-MAX#` / `#GEN:pkg:<name>#`, безопасный маркер пропуска `#SKIP#` (в системный `.env` записывается как `""  # #SKIP#`), сохранение комментариев и инлайн-комментариев при upsert, просмотр реальных значений через `deploy-engine config <pkg> --show [--json] [--reveal]`, редактор по умолчанию `vim -> vi -> nano`.
  - Централизованное снятие атрибута `com.apple.quarantine` на macOS и корректный перехват `Ctrl+C` (`KeyboardInterrupt`) с атомарным `LIFO`-откатом (`TransactionManager`).
- **Алиасы по имени папки, автопоиск каталогов и фильтрация шаблонов**:
  - Автоматический поиск репозитория пакетов по трем стандартным названиям: `packages`, `deploy-packages`, `deploy_packages`.
  - Автоматическая регистрация алиасов как по каноническому имени пакета, так и по имени его папки на диске (например, `vpn-server/amneziawg` и `amneziawg` -> `vpn-server/awg`).
  - Автоматическое игнорирование шаблонных и служебных директорий с префиксом `_` (`_template-py`, `_template-ts`).
- **Интеллектуальный кэш метаданных (`packages.json`)**:
  - При запуске структура пакетов мгновенно считывается из кэша, если возраст кэша не превышает **60 минут** и файлы манифестов не изменялись.
  - Команда `scan` или флаг `--rescan` принудительно переобходят файловую систему и обновляют кэш.
- **Сохранение пути к манифесту в `state.json` и приоритет манифестов**:
  - При установке каждого пакета в `/etc/default/state.json` сохраняется абсолютный путь к его `manifest.json` (`manifest_path`).
  - Установленные пакеты вне текущего манифеста догружаются с пометкой `(внешний)` (полная функциональность) или `! (манифест удален)` (управление службой и просмотр логов).
- **Потоковое логирование операций (`install_DATE.log`)**:
  - Построчный потоковый вывод (`stdout` + `stderr`) пакетных менеджеров (`apt-get`, `dnf`, `apk`, `pacman`, `brew`), `pip`, `npm` и хуков в реальном времени в окно TUI и в `/var/lib/de_<pkg>/install_YYYYMMDD_HHMMSS.log`.
- **Хранилище постоянных динамических данных (`data`) и неразрушающий `.env` (`EnvUpsertManager`)**:
  - Юниты `data` (`/var/lib/de_<pkg>/`) никогда не перезаписываются при обновлении или переустановке.
  - Юниты `env` (`/etc/default/de_<pkg>/<pkg>.env`) дополняются только новыми ключами без затирания существующих секретов (сброс только по `--clean-env`).

## 💻 Графический TUI-интерфейс (Textual)

Трехколоночный интерфейс на всю высоту терминала (все иконки подобраны со строгой шириной `East_Asian_Width=W` для идеального выравнивания рамок в macOS Terminal и iTerm2):

1. **Левая колонка — единый список пакетов (`📦 Пакеты`)**:
   - Отображает пакеты с запланированными действиями, их **транзитивные зависимости** (с пометкой `(зависимость)`) и уже установленные в системе пакеты.
   - Пакеты с действиями и их зависимости всегда выводятся вверху списка (`+` установка, `↻` переустановка, `-` удаление, `💾` бэкап, `🔄` восстановление).
   - **Клик или нажатие `Enter`** на пакете открывает модальное окно **карточки пакета (`PackageDetailsModal`)** с вкладками `📋 Информация`, `📜 Лог установки`, `🔧 Логи службы` и кнопками управления службой/пакетом.
2. **Центральная колонка — дерево пакетов и предпросмотр плана**:
   - Установленные пакеты содержат вложенный пункт **«💾 Создать бэкап»** и список **«🔄 Восстановить из бэкапа»**.
3. **Правая колонка — настройки Sandbox и выполнение в TUI (`ExecutionModal`)**:
   - Переключение режима песочницы (`Sandbox`) и целевой ОС (`debian`, `ubuntu`, `alpine`, `arch`, `fedora`, `macos`) на лету.
   - Нажатие **«Выполнить план»** открывает многовкладочное модальное окно **`ExecutionModal`**:
     - Вкладка **`📋 Общий лог`** и отдельные вкладки **`📦 <пакет>`** для каждого устанавливаемого пакета (уже установленные в системе зависимости автоматически пропускаются как при `install`, так и при `reinstall`).
     - На вкладках раздельно отображаются **статус принятия `.env`** (`❗` — не заполнены обязательные поля, `🔧` — ожидает подтверждения, `🔒` — `.env` принят) и **статус установки пакета** (`📦` в очереди -> `⏳` выполняется -> `✅` сразу по завершении установки пакета, либо `❌` при ошибке).
     - На вкладке каждого пакета с `.env` размещена встроенная компактная панель **`PackageEnvPanel`** (перекрывающая пустой лог до подтверждения).
     - **Обязательное подтверждение `.env` до начала установки**: перед запуском `apt-get`/`brew` и копированием файлов окно поочередно запрашивает подтверждение `.env` только для пакетов без сохраненного пресета (кнопка **`✅ Принять .env`** заблокирована при пустых `[❗ ОБЯЗАТЕЛЬНО]`, кнопка **`✖ Отмена`** прерывает установку до изменений в системе).
     - **Живой индикатор и логи с временем**: каждая строка лога снабжается временем `[HH:MM:SS]`, логи очищаются при каждой новой установке, а во время обновления кэша/установки системных пакетов работает неблокирующий Брайль-спиннер с таймером `[MM:SS]`.
     - **Внутреннее хранилище пресетов**: редактирование `.env` в TUI сохраняет пресет в `DE_LOCAL_ENV_DIR`, не изменяя репозиторий пакетов, а для уже установленных пакетов предлагает кнопку **`🚀 Сохранить и применить в системный .env`**.
4. **Универсальная поддержка русских хоткеев (`RU <-> EN`)**:
   - Двойное нажатие **`q-q`** или **`й-й`** в течение 1 секунды — выход из TUI.
   - Клавиша **`e`** или **`у`** — открытие компактного редактора `.env` для выбранного пакета.

## 🌐 Веб-модуль для панели `de-web` (`web/` и `web-src/`)

Начиная с версии `3.1.0`, `deploy-engine` включает нативный веб-модуль (`"type": "web"` в `manifest.json`, устанавливается в `/opt/de_deploy-engine/web`), реализующий функциональность TUI и расширенные инструменты оркестрации прямо в панели `de-web`:

- **Среды выполнения**: локальный хост (`Live`), песочница (`Sandbox`: `debian`, `ubuntu`, `alpine`, `arch`, `fedora`, `macos`) и `Dry-Run`.
- **Дерево пакетов и план**: выбор действий (`install`, `reinstall`, `upgrade`, `uninstall`), точечное обновление отдельных юнитов (`web`, `files`, `unit`, `script`, `env`, `symlink` + опция `--with-hooks`), резервное копирование и восстановление, обновление базы `deploy-packages` (`git pull --ff-only` + `scan`).
- **Инспектор и мастер `.env`**: просмотр развернутых значений (`config <pkg> --show` с маскированием секретов и ACL-разрешением `env.reveal`), редактирование пресетов/системного `.env` и обязательный мастер подтверждения `.env` до запуска задачи (с поддержкой `#GEN:...#`, `#AUTO#`, `#SKIP#`).
- **Фоновые задачи и аудит**: выполнение плана в отдельном процессе (`web/job_worker.py`), live-потоковые логи (общая вкладка + вкладки по пакетам), безопасная отмена через `SIGINT` с атомарным `LIFO`-откатом (`TransactionManager`), блокировка параллельных live-задач и постоянная история запусков (`/var/lib/de_deploy-engine/web_jobs`).
- **ACL-модель (`web/web.json`, `schema_version: 2`)**: права `view`, `plan.execute`, `sandbox.run`, `env.read`, `env.write`, `env.reveal`, `service.control`, `backup.manage`, `repo.sync`, `jobs.cancel`, `logs.read` (роль `admin: ["*"]`, роль `operator: ["view", "sandbox.run", "env.read", "logs.read"]`).
- **Сборка фронтенда**:
  ```bash
  node web-sdk/build-module.mjs deploy-engine
  ```

## 🔑 Команды и ключи запуска CLI / TUI

### Позиционные команды (`pos_args`)

| Команда | Назначение |
| :--- | :--- |
| *(без команды)* / `tui` | Запуск интерактивного трехколоночного TUI-интерфейса |
| `install <пакет\|пакет:юнит...>` | Транзакционная установка пакетов (или точечное обновление юнитов) |
| `reinstall <пакет\|пакет:юнит...>` | Переустановка пакетов (или точечное обновление отдельных юнитов) с сохранением `data` и `.env` |
| `upgrade [пакет\|all]` | SemVer-обновление только устаревших установленных пакетов с автобэкапом |
| `uninstall <пакет...>` | Удаление пакетов с авто-остановкой служб (сохраняет `data` и `.env` без `--purge`) |
| `config <пакет> [--preset] [--show] [--reveal]` | Редактирование `.env` (редактор `$VISUAL`/`$EDITOR`/`vim`/`vi`/`nano`) или просмотр развернутых значений (`--show`) |
| `backup <пакет\|all>` | Создание архива резервной копии данных и `.env` пакета |
| `restore <пакет\|all> [N]` | Восстановление данных и `.env` пакета из архива бэкапа |
| `list` | Вывод таблицы (или JSON) установленных пакетов с индикацией SemVer-обновлений |
| `info <пакет...>` | Подробная информация о пакете, версии, статусе обновления, категории и путях файлов |
| `completion [commands\|packages\|installed]` | Вывод подсказок для автодополнения Zsh/Bash в формате `имя:описание` |
| `scan` | Принудительное пересканирование директорий пакетов и обновление `packages.json` |
| `version` | Вывод текущей версии Deploy Engine |
| `help` | Вывод справки по командам и ключам запуска |

| Ключ | Аргумент | Описание |
| :--- | :--- | :--- |

| `--info`, `-i` | `[ПАКЕТ]` | Показать описание пакета, статус и пути установки |

| `--reveal` | — | Показать секретные значения без маскирования (используется вместе с `config --show`) |
| `--only` | `<ЮНИТЫ>` | Точечное обновление перечисленных через запятую юнитов (`--only web,files`) |
| `--unit-type` | `<ТИП>` | Точечное обновление юнитов указанного типа (`web`, `file`, `script`, `unit`, `env`, `data`, `symlink`) |

| `--manifest`, `-m` | `<ПУТЬ>` | Путь к `manifest.json` пакета или к корневой папке дерева пакетов |

| `--list`, `-l` | — | Показать список доступных резервных копий (для `backup` и `restore`) |

| `--sandbox-dir` | `<ПУТЬ>` | Путь к директории локальной песочницы (по умолчанию `./.de_sandbox`) |
| `--dry-run`, `-n` | — | Симуляция выполнения операций без модификации файловой системы |
| `--purge` | — | Полное удаление каталогов `ENV` и `Data` при удалении пакета (`uninstall`) |
| `--clean-env` | — | Сброс переменных окружения `.env` к заводским значениям из шаблона при установке |

| `--remote`, `-r` | `<ХОСТ>` | Выполнение команды или TUI на удаленном сервере по SSH (`[user@]host[:port]`) |
| `--remote-dir` | `<ПУТЬ>` | Путь к `deploy-engine` на удаленном сервере (по умолчанию `/opt/de_deploy-engine`) |
| `--config` | `<ФАЙЛ>` | Путь к пользовательскому `.env`-файлу конфигурации самого движка |
| `--yes`, `-y` | — | Неинтерактивный режим CLI (использует пресеты и дефолты `.env`; поддерживает `#SKIP#` для пропуска необязательных полей) |
| `--json` | — | Вывод результатов (`list`, `info`, `config --show`, `upgrade`, `version`, `backup`, `restore`) в формате JSON |
| `--verbose`, `-v` | — | Подробный отладочный вывод всех файловых и системных операций |

## 🌐 Переменные окружения (ENV)

Конфигурация движка загружается иерархически (`lib/config.py`):
`os.environ` -> `--config <файл>` / `DE_CONFIG_PATH` -> `/etc/default/de_deploy-engine/deploy-engine.env` -> `files/app.env` -> встроенные значения по умолчанию.

| Переменная ENV | Значение по умолчанию (system / local) | Описание |
| :--- | :--- | :--- |
| `DE_CONFIG_PATH` | `""` | Путь к кастомному файлу конфигурации движка (альтернатива ключу `--config`) |
| `DE_NONINTERACTIVE` | `""` (`1` / `true`) | Отключение интерактивных запросов `/dev/tty` в CLI (аналог флага `--yes`) |
| `DE_DATA_DIR` | `/var/lib/de_deploy-engine` | Базовый каталог данных установленного в систему движка |
| `DE_PACKAGES_DIR` | `/var/lib/de_deploy-engine/packages` (или `./packages`) | Каталог поиска пакетов по умолчанию |
| `DE_PACKAGES_CACHE` | `/var/lib/de_deploy-engine/packages.json` (или `./packages.json`) | Путь к файлу кэша проиндексированных манифестов |
| `DE_LOCAL_ENV_DIR` | `/var/lib/de_deploy-engine/env` (или `./env`) | Каталог сохранения пользовательских пресетов `.env` (`<pkg>.env`) |
| `DE_BACKUP_DIR` | `/var/lib/de_deploy-engine/backup` (или `./backup`) | Каталог хранения архивов резервных копий пакетов |
| `DE_REMOTE_ENGINE_DIR` | `/opt/de_deploy-engine` | Путь к установленному `deploy-engine` на удаленном сервере для режима `--remote` |
| `DE_SYS_BIN` | `#AUTO#` (`/usr/local/bin` / `/opt/homebrew/bin` / `~/.local/bin`) | Системный каталог для исполняемых скриптов и симлинков |
| `DE_SYS_SYSTEMD` | `#AUTO#` (`/etc/systemd/system` / `/Library/LaunchDaemons` / `~/Library/LaunchAgents`) | Системный каталог для юнитов служб (`systemd` / `launchd`) |
| `DE_ENV_PATH` | `#AUTO#` (`/etc/default` / `~/.config/deploy-engine/default`) | Базовый каталог для хранения `.env` пакетов (`de_<pkg>/`) |
| `DE_STATE_DIR` | `#AUTO#` (`/var/lib` / `~/.local/state/deploy-engine`) | Базовый каталог для постоянных данных пакетов (`de_<pkg>/`) |
| `DE_OPT_DIR` | `#AUTO#` (`/opt` / `~/.local/opt`) | Базовый каталог для рабочих файлов пакетов (`de_<pkg>/`) |
| `DE_VENV_PATH` | `#AUTO#` (`/opt/de_deploy-engine/files/.venv` или `./.venv`) | Путь к виртуальному окружению Python для TUI (`Textual`) |

## 🚀 Примеры использования

```bash
# Запуск интерактивного TUI
python3 deploy-engine/files/main.py
python3 deploy-engine/files/main.py ./deploy-packages --sandbox macos

# Сканирование базы пакетов и инспекция
python3 deploy-engine/files/main.py scan -d ./deploy-packages
python3 deploy-engine/files/main.py list
python3 deploy-engine/files/main.py info local-tools/ssh-profile

# Установка, переустановка и удаление в CLI
sudo python3 deploy-engine/files/main.py install local-tools/server-bootstrap --yes
sudo python3 deploy-engine/files/main.py reinstall local-tools/ssh-profile
sudo python3 deploy-engine/files/main.py uninstall local-tools/server-bootstrap --purge

# Резервное копирование и восстановление
python3 deploy-engine/files/main.py backup all -c "Перед обновлением"
python3 deploy-engine/files/main.py backup --list
sudo python3 deploy-engine/files/main.py restore my-service 1

# Удаленное управление по SSH (CLI и Remote TUI)
python3 deploy-engine/files/main.py list --remote admin@10.0.0.5
python3 deploy-engine/files/main.py --tui --remote admin@10.0.0.5
```
