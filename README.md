# 🛠️ Универсальный движок развертывания инфраструктуры (Deploy Engine)

Легковесный, гибкий и полностью независимый инструмент в концепции **Infrastructure-as-Code (IaC)**, написанный на Python. Движок позволяет декларативно управлять, синхронизировать и развертывать системные службы `systemd` (сервисы и таймеры), исполняемые скрипты и конфигурационные файлы в Linux-системах с помощью простых JSON-манифестов.

Этот репозиторий содержит исключительно логику деплоера и полностью отделен от ваших приватных конфигурационных данных, скриптов или секретов, что делает его безопасным для использования в Open Source.

## ✨ Ключевые возможности

- **Полное разделение кода и данных (Decoupled)**: Движок не содержит захардкоженных путей или названий серверов. Он работает как абстрактный оркестратор, принимая путь к внешнему `manifest.json` в качестве аргумента.
- **Рекурсивные манифесты (`includes`)**: Позволяет разбивать конфигурацию огромной инфраструктуры на цепочки («матрешки») мелких атомарных микропакетов. Манифесты могут ссылаться друг на друга через относительные пути.
- **Кастомное сопоставление путей и прав**: Вы можете прямо в JSON переопределять целевой системный путь установки файла (`dest`) и маску прав доступа (`mode` в октальном формате). Поддерживаются умные дефолтные значения на основе типов файлов.
- **Два режима работы на выбор**:
  - **Продвинутый графический интерфейс (TUI)**: Красивое интерактивное терминальное меню на базе библиотеки `Textual`, которое на лету рендерит итоговую карту путей при клике на чекбоксы.
  - **Быстрый CLI-режим**: Легковесный запуск на чистом Python без внешних зависимостей. Идеально подходит для фоновых задач, cron-таймеров или CI/CD пайплайнов.
- **Изолированное окружение**: Графический интерфейс при первом запуске автоматически создает локальную папку `.venv` внутри репозитория деплоера для доставки библиотеки `Textual`, не загрязняя системный Python вашего сервера.

## 📁 Структура репозитория

```text
deploy/
├── .gitignore            # Защита репозитория от кэша Python (__pycache__) и виртуального окружения
├── LICENSE               # Лицензия Apache 2.0
├── README.md             # Документация проекта (этот файл)
├── deploy_config.py      # Глобальные системные пути по умолчанию (например, /usr/local/bin)
├── deploy.py             # Точка входа для быстрого CLI-бэкенда (чистый Python)
├── deploy_ui.py          # Точка входа для интерактивного TUI-фронтенда (стартер виртуального окружения)
└── lib/
    ├── __init__.py       # Маркер пакета модулей Python
    ├── engine.py         # Ядро деплоера: рекурсивный парсинг JSON, сбор зависимостей и копирование файлов
    ├── ui_app.py         # Логика интерфейса Textual: отрисовка чекбоксов и динамический лог путей
    └── utils.py          # Служебные утилиты: проверка прав root и автоматический бутстрап .venv
```

## 🚀 Инструкция по использованию

Для работы деплоера необходимо запустить его через `sudo` (так как он управляет системными папками вроде `/etc/systemd/system/`) и передать ему путь к вашему целевому файлу манифеста.

### 1. Интерактивный режим (TUI)
Рекомендуется для ручной настройки серверов. Запустите интерфейс, передав путь к корневому манифесту ваших пакетов:
```bash
sudo ./deploy_ui.py /путь/к/вашим/пакетам/manifest.json
```

### 2. Тихий консольный режим (CLI)
Идеально для автоматизации без участия человека. Укажите путь к манифесту, а затем через пробел перечислите имена пакетов или отдельных файлов, которые нужно установить:
```bash
# Развертывание сборного мега-пакета со всеми зависимостями
sudo ./deploy.py /путь/к/вашей/инфраструктуре/manifest.json full-node-setup

# Точечная установка одного конкретного скрипта или сервиса
sudo ./deploy.py /путь/к/вашей/инфраструктуре/manifest.json amnezia-core vpn-monitor.sh
```

## 📄 Спецификация JSON-манифеста

Файлы манифестов в ваших репозиториях с данными могут использовать гибкие настройки для каждого компонента:

```json
{
  "includes": [
    "../common-packages/manifest.json"
  ],
  "units": {
    "my-script.sh": {
      "type": "script",
      "desc": "Скрипт регулярного обслуживания системы"
    },
    "nginx-site.conf": {
      "type": "config",
      "desc": "Конфигурация реверс-прокси Nginx для сайта",
      "dest": "/etc/nginx/sites-available/app.conf",
      "mode": "644"
    }
  },
  "packages": {
    "app-bundle": {
      "desc": "Пакет: Скрипт обслуживания + Конфиг веб-сервера",
      "include": ["my-script.sh", "nginx-site.conf"]
    }
  }
}
```
