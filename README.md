# 🛠️ Deploy Engine 2.0

**Deploy Engine** — модульный, легковесный и полностью автономный оркестратор развертывания инфраструктуры в концепции **Infrastructure-as-Code (IaC)** на Python.

Движок позволяет декларативно управлять системными службами `systemd` (сервисы и таймеры), исполняемыми скриптами, конфигурационными файлами, постоянными динамическими данными (базами данных) и защищенными переменными окружения в Linux-системах с помощью простых и наглядных JSON-манифестов.

Проект спроектирован по принципу полного разделения логики движка и данных пакетов: он может размещаться в отдельном репозитории и управлять как локальными пакетами, так и развертывать их на удаленные серверы по SSH.

## ✨ Ключевые возможности

- **Иерархический поиск пакетов (`DirectoryCrawler`)**:
  - Автоматический рекурсивный обход каталога пакетов (`./packages` по умолчанию).
  - **Терминальная остановка**: как только в директории обнаружен `manifest.json`, она регистрируется как корень пакета, и деплоер не спускается в ее подкаталоги.
- **Мгновенный кэш метаданных (`packages.json`)**:
  - При запуске структура пакетов считывается из локального кэша за доли миллисекунды.
  - Команда `./deploy.py scan` или флаг `--rescan` принудительно переобходят файловую систему и обновляют кэш.
- **Пространства имен и разрешение конфликтов (`NameCollisionResolver`)**:
  - Пакеты с уникальными именами вызываются коротко (например, `./deploy.py install api`).
  - При обнаружении дубликатов (например, `backend/api` и `frontend/api`) движок требует указать явное пространство имен.
- **Хранилище постоянных динамических данных (`data`)**:
  - Новый тип юнита `data` автоматически монтируется в `/var/lib/de_{pkg}/` с правами `0o600` (каталог `0o700`).
  - **Абсолютная защита от перезаписи**: при повторной установке или обновлении существующие базы данных, ключи или файлы состояния **никогда не перезаписываются**.
  - При обычном удалении пакет удаляет свои бинарники и службы, но сохраняет базу данных (полное удаление возможно только с флагом `--purge`).
- **Неразрушающее слияние переменных окружения (`EnvUpsertManager`)**:
  - При обновлении пакета в целевой файл `/etc/default/de_{pkg}/{pkg}.env` дописываются только **новые переменные**, добавленные в шаблон.
  - Все существующие пользовательские пароли, токены и настройки остаются нетронутыми.
  - Флаг `--clean-env` позволяет принудительно сбросить настройки к заводским из шаблона.
  - Каталоги секретов защищены правами `0o600` (`root:root`) и не удаляются при обычном удалении (удаление только с `--purge`).
- **Топологический граф зависимостей (`DependencyGraph`)**:
  - Взаимные зависимости пакетов (`requires`) автоматически разрешаются по алгоритму Кана в безопасный порядок установки.
  - Обнаружение циклических зависимостей с выводом точной цепочки ошибки.
- **Пакетная установка зависимостей ОС (`SystemPackageManager`)**:
  - Все системные пакеты (`sys_packages`) со всех устанавливаемых модулей объединяются, дедуплицируются и устанавливаются **за один вызов** системного пакетного менеджера (`apt-get install -y ...`).
- **Транзакционность и откат при ошибках (`TransactionManager`)**:
  - Все создаваемые файлы, директории, симлинки и резервные копии перезаписываемых файлов фиксируются в журнале транзакции.
  - В случае ошибки на этапе копирования или выполнения хуков деплоер автоматически производит откат в обратном порядке (LIFO) и восстанавливает прежнее состояние.
- **Режим симуляции (`--dry-run` / `-n`)**:
  - Безопасный предварительный просмотр всех действий (копируемые файлы, пути FHS, права доступа, системные пакеты, хуки) без изменения файлов на диске.
- **Инспекция установленных пакетов (`deploy.py list`)**:
  - Просмотр всех развернутых в системе пакетов на основе `/etc/default/state.json` в виде форматированной таблицы или в формате JSON (`--json`).
- **Удаленное развертывание по SSH (`--remote`)**:
  - Автоматическая сборка легковесного бандла деплоера, передача на целевой сервер и удаленный запуск установки или инспекции.
- **Чистая архитектура 2.0**:
  - Строго 1 класс на файл, ни один файл не превышает 300 строк.

## 🚀 Быстрый старт

### Требования
- Linux (Ubuntu, Debian, CentOS, RHEL, Alpine, Arch) или macOS (для клиентских сценариев).
- Python 3.8+ (стандартная библиотека, без обязательных внешних зависимостей для CLI).
- Для использования графического TUI требуется `sudo` (деплоер автоматически развернет виртуальное окружение `.venv` с библиотекой `textual`).

### 1. Сканирование и индексация доступных пакетов
По умолчанию пакеты располагаются в папке `./packages`:
```bash
./deploy.py scan
```
Команда выполнит терминальный обход дерева каталогов и сохранит метаданные в `packages.json`.

### 2. Просмотр списка установленных пакетов
```bash
# В виде читаемой таблицы
./deploy.py list

# В формате JSON для скриптов и автоматизации
./deploy.py list --json
```

### 3. Симуляция установки (Dry-Run)
Проверьте порядок разрешения зависимостей и планируемые действия без прав root и без изменения системы:
```bash
./deploy.py install base-system --dry-run
./deploy.py install app-service bundle-meta -n
```

### 4. Установка пакетов
```bash
# Установка одного пакета со всеми его зависимостями
sudo ./deploy.py install base-system

# Пакетная установка нескольких пакетов за один вызов
sudo ./deploy.py install base-system app-service monitoring
```

### 5. Обновление и переустановка
```bash
# Стандартная переустановка (существующие секреты ENV и базы данных data сохраняются!)
sudo ./deploy.py reinstall app-service

# Чистая переустановка со сбросом конфигурации ENV к заводским настройкам
sudo ./deploy.py reinstall app-service --clean-env
```

### 6. Удаление пакетов
```bash
# Стандартное удаление: удаляются службы и скрипты, но сохраняются /etc/default/de_{pkg} и /var/lib/de_{pkg}
sudo ./deploy.py uninstall app-service

# Полное удаление с очисткой секретов и динамических данных
sudo ./deploy.py uninstall app-service --purge
```

### 7. Удаленное управление по SSH
```bash
# Установка пакета на удаленный сервер
./deploy.py install app-service --remote admin@remote-server.internal

# Удаленная проверка установленных пакетов
./deploy.py list --remote admin@remote-server.internal
```

## 📦 Анатомия пакета Deploy Engine

Каждый пакет представляет собой изолированную директорию с файлом `manifest.json`.

```text
packages/
└── my-service/
    ├── manifest.json       # Декларативный паспорт пакета
    ├── deploy.env          # Шаблон переменных окружения
    ├── my-service.sh       # Исполняемый скрипт
    ├── my-service.service  # Юнит systemd
    ├── files/              # Внутренние файлы и ресурсы
    │   └── config.yaml
    └── data/               # Исходные шаблоны для данных
        └── initial.db
```

### Пример `manifest.json`

```json
{
  "name": "my-service",
  "version": "1.0.0",
  "description": "Автономный фоновый сервис обработки данных",
  "requires": ["setup-base"],
  "sys_packages": ["curl", "jq", "sqlite3"],
  "units": {
    "deploy.env": {
      "type": "env",
      "desc": "Конфигурация переменных окружения и токенов"
    },
    "my-service.sh": {
      "type": "script",
      "desc": "Системный лаунчер приложения"
    },
    "my-service.service": {
      "type": "unit",
      "desc": "Системная служба systemd"
    },
    "database.sqlite": {
      "type": "data",
      "src": "data/initial.db",
      "desc": "Постоянная база данных (никогда не перезаписывается)"
    },
    "my-cli": {
      "type": "symlink",
      "symlink": "{{SYS_BIN}}/my-service.sh",
      "desc": "Символическая ссылка для быстрого вызова"
    }
  },
  "pre_install": "echo 'Подготовка к установке...'",
  "post_install": [
    "systemctl daemon-reload",
    "systemctl enable --now my-service.service"
  ],
  "pre_uninstall": "systemctl stop my-service.service || true",
  "post_uninstall": "systemctl daemon-reload"
}
```

## 🗂️ Типы юнитов и FHS-маршрутизация

| Тип | Стандартный путь в Linux | Права | Описание |
|:---|:---|:---|:---|
| `script` | `{{SYS_BIN}}/<name>` (`/usr/local/bin`) | `0o755` | Исполняемые системные утилиты и лаунчеры |
| `unit` / `service` | `{{SYS_SYSTEMD}}/<name>` (`/etc/systemd/system`) | `0o644` | Фоновые службы systemd |
| `timer` | `{{SYS_SYSTEMD}}/<name>` (`/etc/systemd/system`) | `0o644` | Системные таймеры планировщика systemd |
| `env` | `{{ENV_PATH}}/de_{pkg}/{pkg}.env` (`/etc/default/...`) | `0o600` | Изолированные секреты с неразрушающим слиянием |
| `data` | `{{STATE_DIR}}/de_{pkg}/<name>` (`/var/lib/...`) | `0o600` | Постоянные данные и БД. **Никогда не перезаписываются** |
| `symlink` | `{{SYS_BIN}}/<link_name>` | `0o777` | Символические ссылки |
| `file` | Указанный `target` или `/etc/{pkg}/<name>` | `0o644` | Статические конфигурационные файлы |

## 🧪 Тестирование

Для запуска полного набора модульных тестов:
```bash
python3 -m unittest tests/test_deploy_engine.py
```
Тестовый набор покрывает:
- Терминальный рекурсивный обход директорий.
- Разрешение коллизий одинаковых имен пакетов.
- Работу с кэшем `packages.json`.
- Топологическую сортировку Кана и детекцию циклов.
- Неразрушающий ENV upsert и опцию `--clean-env`.
- Защиту юнитов `data` от перезаписи.
- Транзакционный LIFO-откат при сбоях.
- Инспекцию состояния установленных пакетов.
