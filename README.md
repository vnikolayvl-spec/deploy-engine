# 🛠️ Универсальный движок развертывания инфраструктуры (Deploy Engine)

Легковесный, расширяемый и полностью независимый инструмент в концепции **Infrastructure-as-Code (IaC)**, написанный на Python. Движок позволяет декларативно управлять, синхронизировать и развертывать системные службы `systemd` (сервисы и таймеры), исполняемые скрипты, символьные ссылки, конфигурационные файлы и защищенные файлы переменных окружения в Linux-системах с помощью простых JSON-манифестов.

Этот репозиторий содержит исключительно абстрактную логику деплоера и полностью отделен от ваших приватных конфигурационных данных, скриптов или секретов, что делает его безопасным для использования в Open Source.

## ✨ Ключевые возможности

- **Полное разделение кода и данных (Decoupled)**: Движок не содержит захардкоженных путей или названий серверов. Он работает как изолированный оркестратор, принимая путь к внешнему `manifest.json` в качестве аргумента.
- **Рекурсивные манифесты (`includes`)**: Позволяет разбивать конфигурацию огромной инфраструктуры на цепочки («матрешки») мелких атомарных микропакетов. Манифесты могут ссылаться друг на друга через относительные пути.
- **Внутренние зависимости (`requires`)**: Пакеты могут автоматически подтягивать за собой другие пакеты или общие библиотеки (например, `shared-lib`), декларируя их в блоке зависимостей.
- **Системные зависимости (`sys_packages`)**: Перед началом копирования файлов движок автоматически определяет менеджер пакетов ОС (APT или YUM) и бесшумно доставляет необходимый софт в систему (`apt-get install`).
- **Конвенция ресурсов (`files/`)**: Поддерживает выделенные каталоги `files/` внутри модулей. Все конфигурации и статические ресурсы автоматически изолируются и зеркально разворачиваются на сервере по пути `/etc/de_{имя_пакета}/files/`.
- **Поддержка символьных ссылок (`symlinks`)**: Умеет атомарно создавать мягкие ссылки (`ln -sf`), избавляя от необходимости дублировать тяжелые папки с кодом и позволяя выводить утилиты в глобальный `/usr/local/bin`.
- **Контекстный Sandboxing секретов (`env`)**: Генерирует изолированные `.env`-файлы настроек для приложений в директории `/etc/default/de_{имя_пакета}/` строго с правами доступа `600` (только для root).
- **Интеллектуальный парсинг `{{PROMPT:...}}` прямо из файлов**: Деплоер сканирует `.env`-файлы в поисках маркеров промптов, интерактивно запрашивает секреты у пользователя с выводом текстовых подсказок (`notice`) и производит трехступенчатое `Upsert`-слияние, сохраняя старую историю сервера и не затирая чужие переменные.
- **Хуки жизненного цикла (`post_install` / `pre_uninstall`)**: Выполнение любых кастомных shell-команд или локальных скриптов автоматизации на этапах подготовки и финальной очистки системы.
- **Автоматическая генерация паспорта пакета (`pack.env`)**: По завершении установки деплоер оставляет в системе защищенный файл с Bash-массивами путей (`SCRIPTS`, `TIMERS`, `UNITS`, `FILES`), позволяя внутренним скриптам динамически определять ресурсы через `source`.
- **Управление жизненным циклом и реестр состояний**: Ведет строгий учет развернутых файлов в `/etc/default/state.json`. Поддерживает три явных CLI-действия: `install` (установка), `uninstall` (бесследный снос вместе с песочницами и systemd) и `reinstall` (чистый перезапуск цикла).
- **Умное управление `root_dir`**: По умолчанию `{{ROOT_DIR}}` вычисляется автоматически как папка на уровень выше манифеста (корень репозитория). Вы можете переопределить это поведение в JSON, указав относительный откат (`"root_dir": ".."`) или абсолютный системный путь.

## 📁 Структура репозитория

```text
deploy-engine/
├── .gitignore            # Защита репозитория от кэша Python (__pycache__), packages.json и .venv
├── LICENSE               # Лицензия Apache 2.0
├── README.md             # Документация проекта (этот файл)
├── deploy_config.py      # Настройки путей по умолчанию, корня сандбокса ENV_PATH и префикса ENV_PREFIX
├── deploy.py             # Точка входа для быстрого CLI-бэкенда (install / uninstall / reinstall)
├── deploy_ui.py          # Точка входа для интерактивного TUI-фронтенда
├── packages.json.example # Шаблон локального реестра для автоматического поиска манифестов
└── lib/
    ├── __init__.py
    ├── engine.py         # Ядро деплоера: диспетчеризация, оркестрация и копирование
    ├── ui_app.py         # Графический интерфейс Textual: трехфлажковое циклическое дерево и Сводный План
    ├── utils.py          # Служебные утилиты: проверка прав root и автоматический бутстрап .venv
    └── modules/          # Изолированные плагины-коннекторы деплоера
        ├── __init__.py
        ├── dependency_resolver.py # Рекурсивный обход дерева манифестов и раскрытие requires
        ├── env_manager.py         # Построчный парсинг {{PROMPT}}, Upsert-слияние и компиляция .env
        ├── lifecycle_hooks.py     # Шаблонизация строк и безопасный запуск shell-команд
        └── sys_packages.py        # Автоопределение ОС и менеджмент системных пакетов (APT/YUM)
```

## 🚀 Инструкция по использованию

Для работы деплоера необходимо запускать его через `sudo` (для управления правами доступа и каталогами `/etc/` / `/usr/local/bin/`).

### 1. Интерактивный режим (TUI-планировщик)
Отрисовывает дерево пакетов и позволяет одной клавишей **`Пробел`** циклически нарезать задачи для серверов:
- `[+]` — **Установить** (для новых компонентов)
- `[↻]` — **Переустановить** (для живых пакетов: снос старого с хуками -> чистая накатка)
- `[-]` — **Удалить** (полная зачистка файлов, песочниц секретов и запуск pre_uninstall)

Запуск:
```bash
sudo ./deploy_ui.py /путь/к/вашему/deploy-packages/manifest.json
# Если настроен файл packages.json, можно запускать без аргументов:
sudo ./deploy_ui.py
```

### 2. Консольный режим (CLI-автоматизация)
Преддназначен для фонового деплоя, cron-таймеров или CI/CD-пайплайнов:
```bash
# Установка (install — экшен по умолчанию)
sudo ./deploy.py /путь/к/manifest.json install amnezia-stat-app

# Полное удаление пакета со всеми хвостами
sudo ./deploy.py /путь/к/manifest.json uninstall amnezia-stat-app

# Быстрая чистая переустановка
sudo ./deploy.py /путь/к/manifest.json reinstall amnezia-stat-app
```

## 📄 Спецификация JSON-манифеста

Движок поддерживает четыре базовых типа юнитов (`type`): `script`, `unit` (или `service`/`timer`), `env` и универсальный тип по умолчанию `file` (для любых статических ресурсов и конфигураций сторонних приложений).

```json
{
  "includes": [
    "../shared-modules/manifest.json"
  ],
  "units": {
    "amnezia-stat.py": {
      "type": "script",
      "desc": "Фоновый демон сбора статистики",
      "root_dir": ".."
    },
    "amnezia-stat.service": {
      "type": "service",
      "desc": "Системный юнит службы трафика"
    },
    "ipsec-bridge.conf": {
      "type": "file",
      "desc": "Конфигурация IKEv2 для strongSwan",
      "dest": "/etc/ipsec.d/bridge.conf",
      "mode": "600"
    },
    "production.env": {
      "type": "env",
      "desc": "Секреты приложения (поддерживает {{PROMPT}} внутри самого файла)",
      "variables": {
        "SERVER_REGION": "EU-WEST"
      }
    }
  },
  "packages": {
    "stat-app": {
      "desc": "Полный пакет статистики с хуками и системным софтом",
      "sys_packages": ["jq", "strongswan"],
      "requires": ["shared-lib"],
      "include": ["stat.py", "stat.service", "ipsec-bridge.conf", "production.env"],
      "post_install": [
        "mkdir -p /var/log/de_stat",
        "systemctl restart strongswan-starter"
      ],
      "pre_uninstall": [
        "rm -rf /var/log/stat"
      ]
    }
  }
}
```
