# 🛠️ Deploy Engine 2.0

**Deploy Engine** — модульный, кроссплатформенный и автономный оркестратор развертывания инфраструктуры в концепции **Infrastructure-as-Code (IaC)** на Python.

Движок позволяет декларативно управлять системными службами (`systemd` в Linux и `launchd` `.plist` в macOS), исполняемыми скриптами, конфигурационными файлами, директориями, правами доступа, постоянными динамическими данными (базами данных), резервными копиями и защищенными переменными окружения с помощью JSON-манифестов (`manifest.json` и `category.json`).

Проект спроектирован по принципу полного разделения логики движка и данных пакетов: он может устанавливаться в систему (`/opt/de_deploy-engine`) как обычный пакет по собственному `manifest.json`, управлять локальными пакетами и развертывать их на удаленные серверы по SSH.

## ✨ Ключевые возможности

- **Единая точка входа (`files/main.py`)**:
  - Запуск без CLI-команды (или с флагом `--tui`) открывает интерактивный графический TUI-интерфейс.
  - Запуск с командой (`install`, `uninstall`, `reinstall`, `backup`, `restore`, `list`, `info`, `scan`, `help`) или флагом `--info` работает в пакетном CLI-режиме.
  - Корректный перехват `Ctrl+C` (`KeyboardInterrupt`) на любом этапе с автоматическим откатом незавершенной транзакции в обратном порядке (`LIFO`).
- **Интеллектуальный кэш метаданных (`packages.json`)**:
  - При запуске структура пакетов мгновенно считывается из кэша, если возраст кэша не превышает **60 минут** и файлы манифестов не изменялись.
  - Команда `scan` или флаг `--rescan` принудительно переобходят файловую систему и обновляют кэш.
- **Сохранение пути к манифесту в `state.json` и приоритет манифестов**:
  - При установке каждого пакета в `/etc/default/state.json` сохраняется абсолютный путь к его `manifest.json` (`manifest_path`).
  - **Приоритет при запуске**: в первую очередь используются пакеты из указанного в команде запуска манифеста или каталога (либо из `./packages` при запуске без аргументов).
  - **Автоподгрузка внешних пакетов**: если установленный в системе пакет отсутствует в целевом манифесте запуска, движок проверяет сохраненный `manifest_path`. Если файл существует — пакет автоматически догружается с пометкой `(внешний)` и сохраняет **полную функциональность**. Если исходный манифест был удален с диска — пакет помечается как `⚠ (манифест удален)`, а в его карточке остаются доступными **управление службой и просмотр логов**.
- **Декларативные директории, права доступа и безопасное удаление**:
  - Секции `dirs` и `chmod` на уровне пакета в `manifest.json`, а также поддержка типа юнита `dir` и поля `mode`/`chmod`.
  - Автоматическое назначение прав `+rX` (`0755`) на создаваемые каталоги и `+x` (`0755`) на `main.py` и `*.sh` внутри `files/`.
  - Полный запрет вызова команды `rm` во всех хуках манифеста (`pre_install`, `post_install`, `pre_uninstall`, `post_uninstall`).
  - При удалении пакета автоматически останавливаются его службы (`systemd` / `launchd`), удаляются файлы и пустой каталог `/opt/de_<pkg>`, а для сохраненных каталогов данных и секретов в терминал выводится готовая команда `sudo rm -rf ...` для ручной очистки.
- **Логирование каждой операции (`install_DATE.log`)**:
  - Каждая установка, переустановка и удаление пакета записывает подробный лог в `/var/lib/de_<pkg>/install_YYYYMMDD_HHMMSS.log`.
- **Хранилище постоянных динамических данных (`data`) и неразрушающий `.env` (`EnvUpsertManager`)**:
  - Юниты `data` (`/var/lib/de_<pkg>/`) никогда не перезаписываются при обновлении или переустановке.
  - Юниты `env` (`/etc/default/de_<pkg>/<pkg}.env`) дополняются только новыми ключами без затирания существующих секретов (сброс только по `--clean-env`).
- **Версионированные бэкапы и восстановление (`backup` / `restore`)**:
  - Сжатые архивы `deploy-engine/backup/<pkg>/<timestamp>.tar.gz` с `backup_meta.json`, поддержкой комментариев `--comment`, мета-цели `all`, выбора архива по номеру или метке времени и защитой от Path Traversal (`Tar Slip`).

## 🖥️ Графический TUI-интерфейс (Textual)

Трехколоночный интерфейс на всю высоту терминала:

1. **Левая колонка — единый список пакетов (`📦 Пакеты`)**:
   - Отображает как пакеты с запланированными действиями, так и уже установленные в системе пакеты.
   - **Пакеты с запланированными действиями** всегда выводятся **вверху списка** (сразу под «📋 Все пакеты»), при этом галочка `✓` заменяется на желтую вращающуюся стрелку `↻` (переустановка), красный минус `-` (удаление) или зеленый плюс `+` (установка), дополняясь значками `💾` (бэкап) и `♻️` (восстановление).
   - Установленные пакеты вне текущего манифеста выделяются как `✓ pkg (внешний)` или `⚠ pkg (манифест удален)`.
   - **Клик или нажатие `Enter`** на пакете открывает модальное окно **карточки пакета (`PackageDetailsModal`)**:
     - Вкладка **«📋 Информация»**: статус, версия, путь к манифесту, описание и все системные пути.
     - Вкладка **«📜 Лог установки»**: отображает последний по времени файл `install_DATE.log`.
     - Вкладка **«⚙️ Логи службы»**: статус и журнал `systemctl status` / `journalctl` / `launchctl`.
     - Кнопки управления: **«🔄 Перезапустить службу»**, **«🔐 Настроить .env»**, **«♻️ Переустановить»** / **«🗑️ Удалить»** / **«🎁 Установить»**.
2. **Центральная колонка — дерево пакетов и предпросмотр плана**:
   - Установленные пакеты содержат вложенный пункт **«💾 Создать бэкап»** (выбор пробелом) и лениво подгружаемый список **«♻️ Восстановить из бэкапа»** (выбор до 1 архива на пакет). При одновременном выборе обоих пунктов сначала создается бэкап, затем выполняется восстановление.
3. **Правая колонка — настройки Sandbox и выполнение в TUI**:
   - Переключение режима песочницы (`Sandbox`) и целевой ОС (`debian`, `ubuntu`, `alpine`, `arch`, `fedora`, `macos`) на лету.
   - Нажатие **«Выполнить план»** открывает модальное окно **`ExecutionModal`** непосредственно поверх TUI с живым потоковым логом выполнения и автоматическим обновлением интерфейса по завершении.
4. **Универсальная поддержка русских хоткеев (`RU <-> EN`)**:
   - Все горячие клавиши TUI работают независимо от выбранной раскладки клавиатуры (`ЙЦУКЕН` автоматически транслируется в `QWERTY`, когда фокус не находится в поле ввода `Input`):
     - Двойное нажатие **`q-q`** или **`й-й`** в течение 1 секунды — выход из TUI с всплывающей подсказкой.
     - Клавиша **`e`** или **`у`** — открытие редактора `.env` для выбранного пакета.

## 🚀 Быстрый старт и команды CLI

```bash
# Запуск интерактивного TUI (по умолчанию при вызове без команды)
python3 deploy-engine/files/main.py
python3 deploy-engine/files/main.py ./packages --sandbox debian

# Сканирование пакетов и просмотр установленных пакетов
python3 deploy-engine/files/main.py scan
python3 deploy-engine/files/main.py list
python3 deploy-engine/files/main.py info my-service

# Установка, переустановка и удаление
sudo python3 deploy-engine/files/main.py install my-service
sudo python3 deploy-engine/files/main.py reinstall my-service
sudo python3 deploy-engine/files/main.py uninstall my-service
sudo python3 deploy-engine/files/main.py uninstall my-service --purge

# Резервное копирование и восстановление
python3 deploy-engine/files/main.py backup my-service -c "Перед миграцией"
python3 deploy-engine/files/main.py backup --list
sudo python3 deploy-engine/files/main.py restore my-service 1

# Удаленное управление по SSH (Полный и Сокращенный режимы, Remote TUI)
python3 deploy-engine/files/main.py list --remote admin@10.0.0.5
python3 deploy-engine/files/main.py --tui --remote admin@10.0.0.5
```

## 📦 Пример `manifest.json` с декларативными `dirs` и `chmod`

```json
{
  "name": "my-service",
  "version": "1.2.0",
  "description": "Фоновый сервис обработки данных",
  "requires": ["setup-base"],
  "sys_packages": {
    "apt": ["curl", "jq", "sqlite3"],
    "brew": ["curl", "jq", "sqlite"]
  },
  "dirs": [
    "{{DATA_DIR}}/cache",
    {
      "path": "{{DATA_DIR}}/secrets",
      "mode": "0700",
      "desc": "Защищенный каталог ключей"
    }
  ],
  "chmod": [
    {
      "path": "/opt/de_my-service/files/custom_helper.py",
      "mode": "0755"
    }
  ],
  "units": {
    "deploy.env": { "type": "env", "desc": "Конфигурация окружения" },
    "files": { "type": "file", "dest": "/opt/de_my-service/files", "desc": "Модульное ядро (main.py и *.sh получают 0755 автоматически)" },
    "my-service.sh": { "type": "script", "desc": "Системный лаунчер" },
    "my-service.service": { "type": "unit", "desc": "Служба systemd (конвертируется в launchd .plist на macOS)" },
    "database.sqlite": { "type": "data", "src": "data/initial.db", "desc": "Постоянная БД (не перезаписывается)" }
  },
  "post_install": [
    "systemctl daemon-reload",
    "systemctl enable --now my-service.service"
  ]
}
```
