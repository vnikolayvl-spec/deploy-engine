# 🛠️ Универсальный движок развертывания инфраструктуры (Deploy Engine)

Легковесный, расширяемый и полностью независимый инструмент в концепции **Infrastructure-as-Code (IaC)**, написанный на Python. Движок позволяет декларативно управлять, синхронизировать и развертывать системные службы `systemd` (сервисы и таймеры), исполняемые скрипты, символьные ссылки, конфигурационные файлы и защищенные файлы переменных окружения в Linux-системах с помощью простых JSON-манифестов.

Этот репозиторий содержит исключительно абстрактную логику деплоера и полностью отделен от ваших приватных конфигурационных данных, скриптов или секретов, что делает его безопасным для использования в Open Source.

## ✨ Ключевые возможности

- **Полное разделение кода и данных (Decoupled)**: Движок не содержит захардкоженных путей или названий серверов. Он работает как изолированный оркестратор, принимая путь к внешнему `manifest.json` в качестве аргумента.
- **Рекурсивные манифесты (`includes`)**: Позволяет разбивать конфигурацию огромной инфраструктуры на цепочки («матрешки») мелких атомарных микропакетов. Манифесты могут ссылаться друг на друга через относительные пути.
- **Внутренние зависимости (`requires`)**: Пакеты могут автоматически подтягивать за собой другие пакеты или общие библиотеки (например, `shared-lib`), декларируя их в блоке зависимостей.
- **Системные зависимости (`sys_packages`)**: Перед началом копирования файлов движок автоматически определяет менеджер пакетов ОС (APT или YUM) и бесшумно доставляет необходимый софт в систему (`apt-get install`).
- **Конвенция ресурсов (`files/`)**: Поддерживает выделенные каталоги `files/` внутри модулей. Все конфигурации и статические ресурсы автоматически изолируются и зеркально разворачиваются на сервере по пути `/etc/de_{имя_пакета}/files/`.
- **Поддержка символьных ссылок (`symlinks`)**: Умеет атомарно создавать мягкие ссылки (`ln -sf`), избавляя от необходимости дублировать тяжелые папки с кодом и позволяя выводить утилиты в глобальный `/usr/local/bin`.
- **Контекстный Sandboxing секретов (`env`)**: Генерирует изолированные `.env`-файлы настроек для приложений в директории `/etc/default/de_{имя_пакета}/` строго с правами доступа `600` (только для root).
- **Интеллектуальный парсинг `{{PROMPT:...}}` прямо из файлов**: Деплоер сканирует `.env`-файлы в поисках маркеров промптов, интерактивно запрашивает секреты у пользователя с выводом текстовых подсказок (`notice`) и производит трехступенчатое `Upsert`-слияние, сохраняя старую историю сервера и не затирая чужие переменные.
- **Хуки жизненного цикла (`post_install` / `pre_uninstall`)**: Выполнение любых кастомных shell-команд или локальных скриптов автоматизации на этапах подготовки и финальной очистки системы.
- **Автоматическая генерация паспорта пакета (`pack.env`)**: По завершении установки деплоер оставляет в системе защищенный файл с Bash-массивами путей (`SCRIPTS`, `TIMERS`, `UNITS`, `FILES`), позволяя внутренним скриптам динамически определять ресурсы через `source`.
- **Управление жизненным циклом и реестр состояний**: Ведет строгий учет развернутых файлов в `/etc/default/state.json`. Поддерживает три явных CLI-действия: `install` (установка), `uninstall` (бесследный снос вместе с песочницами и systemd) и `reinstall` (чистый перезапуск цикла).
- **Умное управление `root_dir`**: По умолчанию `{{ROOT_DIR}}` вычисляется автоматически как папка на уровень выше манифеста (корень репозитория). Вы можете переопределить это поведение в JSON, указав относительный откат (`"root_dir": ".."`) или абсолютный системный путь.

```text
    └── modules/          # Изолированные плагины-коннекторы деплоера
        ├── __init__.py

        └── sys_packages.py        # Автоопределение ОС и менеджмент системных пакетов (APT/YUM)
```

## 🚀 Инструкция по использованию

Для работы деплоера необходимо запускать его через `sudo` (для управления правами доступа и каталогами `/etc/` / `/usr/local/bin/`).

### 1. Интерактивный режим (TUI-планировщик)
Отрисовывает дерево пакетов и позволяет одной клавишей **`Пробел`** циклически нарезать задачи для серверов:
- `[+]` — **Установить** (для новых компонентов)
- `[↻]` — **Переустановить** (для живых пакетов: снос старого с хуками -> чистая накатка)
- `[-]` — **Удалить** (полная зачистка файлов, песочниц секретов и запуск pre_uninstall)

Запуск:
```bash
sudo ./deploy_ui.py /путь/к/вашему/deploy-packages/manifest.json
# Если настроен файл packages.json, можно запускать без аргументов:
sudo ./deploy_ui.py
```

### 2. Консольный режим (CLI-автоматизация)
Преддназначен для фонового деплоя, cron-таймеров или CI/CD-пайплайнов:
```bash
# Установка (install — экшен по умолчанию)
sudo ./deploy.py /путь/к/manifest.json install amnezia-stat-app

# Полное удаление пакета со всеми хвостами
sudo ./deploy.py /путь/к/manifest.json uninstall amnezia-stat-app

# Быстрая чистая переустановка
sudo ./deploy.py /путь/к/manifest.json reinstall amnezia-stat-app
```

## 🗺️ Стандартные пути установки по умолчанию (Path Conventions)

Если в JSON-манифесте для конкретного юнита (компонента) **не указан** кастомный параметр `"dest"`, движок автоматически вычисляет системный путь назначения и выставляет безопасные права доступа на основе типа (`type`) или расширения файла:

| Тип юнита (`type`) | Расширение / Конвенция | Системный путь по умолчанию (`dest`) | Права (`mode`) | Описание |
| :--- | :--- | :--- | :--- | :--- |
| `service` / `timer` | `.service`, `.timer` | `/etc/systemd/system/[имя_файла]` | `644` | Системные службы и таймеры автоматизации |
| `script` | `.sh`, `.py` | `/usr/local/bin/[имя_файла]` | `755` | Исполняемые утилиты и CLI-скрипты |
| `env` | — | `/etc/default/de_{имя_пакета}/[имя_файла]` | `600` | Изолированные секреты и настройки приложения |
| `file` | Конфиги, сертификаты, данные | `/opt/de_{имя_пакета}/files/[относительный_путь]` | `644` | Любые статические ресурсы и иерархия папок из `files/` |

> 🔒 **Важно для безопасности**: Вся директория настроек окружения (`/etc/default/de_*/`) и находящиеся в ней скомпилированные файлы секретов, включая сгенерированный паспорт ресурсов `pack.env`, намертво закрываются правами доступа `600` и принадлежат исключительно пользователю `root:root`.

## 📋 Спецификация написания манифестов (`manifest.json`)

Манифест является главным декларативным документом для **Deploy Engine**. Он описывает структуру метапакетов, зависимости операционной системы (`sys_packages`), состав дистрибутива (`include`), а также жизненный цикл пост-установки (`post_install`).

### 1. Архитектура корневых объектов

Манифест состоит из двух ключевых JSON-объектов верхнего уровня:
*   `"packages"` — декларация логических пакетов (метапакетов) для установки.
*   `"units"` — атомарное описание каждого файла, скрипта, сервиса или директории.

---

### 2. Справочник типов юнитов (`units`)

Каждому элементу в блоке `"units"` должен быть присвоен строго определенный тип (`type`), который определяет поведение конвейера оркестрации:

| Тип юнита (`type`) | Назначение | Поведение движка |
| :--- | :--- | :--- |
| `script` | Исполняемые файлы автоматизации. | Копируется в системный бинарный путь с правами `755`. |
| `unit` / `service` | Системные юниты `systemd` (сервисы, сокеты). | Копируются в директорию systemd, автоматически регистрируются через `systemctl enable`. |
| `file` | Статические файлы или **целые директории**. | Копируются рекурсивно. Спец-файлы (`.sock`, `FIFO`) автоматически изолируются и пропускаются. |
| `env` | Шаблоны конфигураций и секретов. | Парсит маркеры `{{PROMPT:...}}`, интерактивно запрашивает ввод через `/dev/tty`, сохраняет историю. |

---

### 3. Анатомия конфигурации окружения (`type: "env"`)

Движок поддерживает **трехступенчатое слияние (Merge-Pipeline)** для конфигурационных файлов:
1.  **Парсинг исходного шаблона:** Считывает пары `KEY=VALUE`. При обнаружении конструкции `{{PROMPT:Текст подсказки}}` ставит переменную в очередь на интерактивный запрос.
2.  **Защита State-Compliance:** Если файл на целевом сервере уже существует, старые заполненные значения *не перезаписываются* пустыми промптами.
3.  **Интерактивный сеанс:** Запрашивает у администратора ввод через терминал `/dev/tty` (совместимо с TUI/curses), после чего сохраняет итоговый файл с правами `600` (владелец `root:root`).

---

### 4. Комплексный эталонный пример

Пример манифеста для развертывания фонового сервиса нотификации с сокет-активацией, шаблонизацией секретов и копированием папки исходного кода:

```json
{
  "packages": {
    "notifier": {
      "desc": "Универсальный сервис нотификаций с поддержкой Telegram, UNIX-сокетов и Jinja2 шаблонов",
      "sys_packages": [
        "python3",
        "python3-pip",
        "python3-jinja2"
      ],
      "include": [
        "notifier.sh",
        "notifier.socket",
        "notifier.service",
        "deploy.env",
        "files"
      ],
      "post_install": [
        "systemctl daemon-reload",
        "systemctl enable notifier.socket",
        "systemctl start notifier.socket"
      ]
    }
  },
  "units": {
    "notifier.sh": {
      "type": "script",
      "desc": "Прокладка-запускчик для единой точки входа в систему"
    },
    "notifier.socket": {
      "type": "unit",
      "desc": "Системный юнит UNIX-сокета для Socket Activation"
    },
    "notifier.service": {
      "type": "unit",
      "desc": "Системный сервис для фонового демона нотификатора"
    },
    "deploy.env": {
      "type": "env",
      "desc": "Шаблон секретов (Токен, Chat ID)",
      "dest": "/etc/default/de_notifier/notifier.env"
    },
    "files": {
      "type": "file",
      "desc": "Исходный код Python-сервиса и папка Jinja2 шаблонов (копируется рекурсивно)",
      "dest": "/opt/de_notifier/files"
    }
  }
}
```

### 5. Правила валидации путей и перегрузок

1.  **Приоритет назначения (`dest`):** Если внутри описания юнита в блоке `"units"` явно указан параметр `"dest"`, движок проигнорирует стандартные системные пути и принудительно запишет файл/директорию по указанному абсолютному адресу.
2.  **Контекстные маркеры:** В путях и текстовых файлах поддерживается автоматическая замена макросов:
    *   `{{ROOT_DIR}}` — Корневая директория выполнения.
    *   `{{BASE_DIR}}` — Директория, в которой физически расположен файл манифеста `manifest.json`.
    *   `{{SYS_BIN}}` — Путь к бинарным файлам системы (из `deploy_config.py`).
    *   `{{SYS_SYSTEMD}}` — Путь к системным юнитам systemd.
